# FinVest 개발 메모

## 실행 방법

프로젝트 루트에서 실행한다.

```bash
npm install
npm run dev
```

배포 또는 제출 전 최소 검증은 아래 명령으로 수행한다.

```bash
npm run build
```

현재 별도 테스트 스크립트는 없으므로 주요 화면은 브라우저에서 직접 확인한다.

## 로그인 및 회원가입

현재 인증 방식은 이메일 기반 로그인/회원가입이다. SSO 로그인은 사용하지 않는다.

mock 모드에서는 아래 임시 계정으로 로그인할 수 있다.

- 이메일: `student@universion.local`
- 비밀번호: `finvest1234!`

로그인 화면의 `임시 로그인 계정` 버튼을 누르면 위 계정 정보가 자동 입력된다. mock 모드에서도 자동 로그인은 하지 않으며, 실제 기능 화면에 접근하려면 로그인 과정을 거친다.

## 주요 라우팅

- `/`: 랜딩 페이지
- `/login`: 로그인
- `/signup`: 회원가입
- `/home`: 홈
- `/simulation/1`: 투자 시뮬레이터 상세 화면
- `/ai-learning`: AI 학습
- `/challenge`: 챌린지
- `/mypage`: 마이페이지

`/simulation`은 별도 목록 화면으로 사용하지 않고 `/simulation/1`로 이동한다.

## 화면 범위

현재 발표 범위에 맞춰 핵심 화면 중심으로 구성한다.

- 유지: 랜딩, 홈, 투자 시뮬레이터, AI 학습, 챌린지, 마이페이지
- 제외: 뉴스/토론 메뉴, 고객지원, 공지사항, FAQ, 1:1 문의, 푸터, 약관/개인정보 상세 페이지

제외된 화면은 나중에 필요하면 별도 기능으로 다시 추가한다.

## Mock API와 실제 API 전환

기본 실행은 mock API를 사용한다. 실제 백엔드와 연동할 때는 프로젝트 루트에 `.env`를 만들고 아래 값을 설정한다.

```env
VITE_API_BASE_URL=http://localhost:8080/api
VITE_USE_MOCKS=false
```

기존 호환을 위해 `VITE_API_BASE`도 지원한다.

```env
VITE_API_BASE=http://localhost:8080/api
```

## 수동 확인 체크리스트

1. `/`에서 랜딩 페이지가 표시되는지 확인한다.
2. 보호된 메뉴 접근 시 `/login`으로 이동하는지 확인한다.
3. 임시 계정으로 로그인 후 원래 접근하려던 화면으로 복귀하는지 확인한다.
4. `/simulation/1`에서 차트 기간 버튼이 동작하는지 확인한다.
5. 매수/매도 주문 UI에서 mock 주문이 처리되는지 확인한다.
6. `/ai-learning`에서 AI 튜터와 학습 모달이 열리는지 확인한다.
7. `/challenge`와 `/mypage`가 로그인 상태에서 접근되는지 확인한다.
